# 财报事实核验与分析

目标是生成可追溯、口径一致的财务分析。正确性优先于速度、篇幅和角色表现。

## 本地模型执行预算

- 完整报告也必须优先完成交付，不能为了穷尽附注而一直读取到超时。
- 首次读取用目录和较大的非重叠区间定位内容；`read_document` 通常使用 600—1,000 行的区间。可以在一个工具回合并行读取多个已知区间，禁止以几十或一百行为步长线性翻完整份报告。
- 一份常规年报或半年报原则上最多调用 20 次 `read_document`。重复读取同一区间前先说明缺少的具体字段；不要重复读取已经形成高置信度事实的页面。
- 优先保证收入、利润、扣非、三类现金流、现金净变化、应收、存货、流动资产负债、固定资产/在建工程和资本开支正确。次要信息在预算内找不到时标为“报告中未核实”，不要继续无边界搜索。
- 最迟在读取预算还剩四次时停止扩展材料：两次用于解决核心矛盾，两次预留给终审与成文。无论次要项目是否齐全，都要按时给出可用的最终答复。

## 工作流程

1. **定位材料**
   - 确认公司、报告类型、报告期、币种、单位和审计状态。
   - 先读首页至主要财务数据，再用少量大区间定位合并三张报表、管理层讨论、主营业务、研发/项目和风险附注；不要无目的地反复通读整份报告。

2. **建立关键事实账本**
   - 在写分析前，先在当前上下文中整理一张紧凑的核心事实表，无需为账本另写长篇报告。每项必须同时记录：科目、合并或母公司口径、本期或比较期、时点或期间、单位、数值、页码或可复查行号、原文证据。
   - 用户未明确要求母公司口径时，以合并报表为主。母公司数据只能明确标注后作为补充，绝不能混入合并分析。
   - 表格列错位、负号或空白不清时，必须在摘要、完整报表或附注中寻找第二处证据。无法确认就标为“未核实”，不要猜数。

3. **先校验，再推理**
   - 完整分析时必须读取并执行 [财务校验规则](references/financial-validation.md)。
   - 比率、同比和加总使用可用的计算工具或 shell 计算，不依赖心算。
   - 任何核心勾稽失败都先回到原表修正。不能通过校验的核心数字不得支撑结论。
   - 第二处证据只用于核心数字、解析歧义或勾稽失败；不要为了形式完整而给每个次要数字寻找重复证据。

4. **分模块分析**
   - 收入与利润质量：增长来源、成本增速、毛利率、费用、归母与扣非差异。
   - 现金流：经营造血、投资与资本开支、筹资、现金净变化及其勾稽。
   - 资产负债与营运资本：现金、应收、存货、流动性、债务、在建工程和固定资产。
   - 主营业务与项目：分产品经营变化、产能/项目进度、研发投入和商业化证据。
   - 风险与跟踪指标：每项风险必须对应已核实事实；跟踪指标要给出口径或计算方法。

5. **成文与终审**
   - 明确区分“报告事实”“计算结果”和“分析判断”。每个关键结论至少绑定一项事实证据。
   - 角色语气只能在事实和分析完成后轻量加入，不得改写数字、口径或置信度。
   - 交付前逐项反查所有金额、百分比、正负号、期间、单位和合并口径。发现矛盾时修正正文，而不是仅增加 OCR 免责声明。

## 输出要求

- 至少覆盖用户指定的模块，并优先呈现最重要的三至五条结论。
- 关键数字尽量标注报告页码或可定位的表名/附注；未核实内容必须明确说明。
- 不把管理层表述直接当作分析结论；说明事实之后再给判断和不确定性。
- 除非用户明确要求，不使用报告期后的信息，不进行股价预测，不把参考答案当作事实来源。
- 若任务范围较窄，可缩减模块，但事实账本、口径核对和终审规则仍然适用。
