# 聊天记录按需加载与搜索

私聊（含私密、无痕会话）、群聊、世界会话共用同一套交互：

- 打开会话只请求最近 40 条原始记录；向上滚动到顶部或点“加载更早记录”继续读取。
- 当前页面最多保留 160 条原始记录；向更早处浏览时释放较新的页面，通过“加载后续记录”或“回到最新”恢复。不删除数据库中的记录。
- 聊天图片在进入视口附近时才设置图片地址；未改变的消息复用 DOM，避免流式输出重复创建整段图文。
- 顶部放大镜或 Ctrl/Cmd+F 打开当前会话的全文搜索。每次返回 20 条结果，点击结果加载其附近的一小段记录并高亮定位。
- 后台刷新保留历史阅读位置。切换会话会取消分页/搜索请求并清空搜索状态；无痕搜索不写入持久化缓存。
- 流式回复按消息批次固定在该批最后一条用户消息之后，正式回复沿用记录分支中的用户消息锚点，不按完成时间重新插队；只调整显示，不重写历史时间戳。
- 后台刷新校验请求顺序、实时事件版本和分页版本，过期结果不能覆盖完成后的界面。正式记录提前入库时仍只显示一个流式气泡；断线重连或历史/队列读取时间不一致时，保留气泡直到正式记录能原位接替。
- 上下文余量收为 18px 小圆环，弧长表示已用比例；正常为中性灰，余量不足时使用警示色。悬停查看数值，点击仍打开原有详情，不常驻显示百分比。

## HTTP 接口

普通及私密私聊支持在生成期间插话：新消息立即请求中止当前轮次，等当前轮次收尾后，保留原始输入和已完成工具结果，结合补充消息继续回复。客户端重试同一个 `clientMessageId` 不会再次打断。

回复准备阶段（包括上下文整理）失败时，用户输入和失败说明仍写入聊天记录。Inbox 快照的 `failedMessages` 另外保留最近 50 条失败输入，供界面恢复旧版本未写入聊天记录的消息；它们不算待发送队列。界面合并时去重，刷新和分页不会丢失失败消息。失败气泡可“放回输入框”，由用户确认后再发送。

上下文预算把图片作为图像输入估算，不按 Base64 传输长度计作文字 token；模型返回实际用量后优先用实际值预测下一轮。压缩后的预算重新计算当前提示词、工具和保留历史，避免把旧的错误估值当成固定开销继续累加。

最新一条正在处理的用户消息可以编辑并重新发送；编辑会中止当前回复，在安全检查通过后替换该条输入。已经完成文件写入、创建日程等操作的轮次不可回滚编辑，应另发纠正消息。停止按钮同时暂停发送队列，未处理消息会保留，重启后仍暂停；点击“继续发送”或发送新消息恢复。

`POST /api/v1/sessions/:id/messages/cancel` 停止当前轮次并暂停队列；`POST /api/v1/sessions/:id/inbox/resume` 恢复队列。Inbox 快照包含 `paused`、`activeBurstId`、`interrupting`，事件流增加 `queue_state` 和 `burst_interrupted`。客户端按批次忽略被中止轮次的迟到流式输出。

以下消息接口增加 `?paged=1&limit=40` 后返回 `{messages, page}`，其中 `page` 包含 `first`、`last`、`hasEarlier`、`hasLater`：

- `/api/v1/sessions/:id/messages`
- `/api/v1/group-chats/:id/messages`
- `/api/v1/worlds/:id/conversation/messages`

`before`、`after`、`around` 接收本会话消息 ID，三者互斥。单页限制为 1–100 条。不带 `paged=1` 的原有接口保持兼容。

在上述路径后加 `/search?q=关键词&limit=20` 返回 `{results, next}`。结果包含 ID、发言者、时间和短摘要，不包含图片二进制或模型思考内容。使用 `before=next` 继续搜索更早的结果。搜索按字面包含匹配，不把 `%` 或 `_` 当作通配符。

私聊继续使用原有 `conversationSpace` / `characterId` 校验；无痕会话从隔离子运行时读取。游标不存在或来自其他会话时返回 404。

## 存储与验证

世界与群聊使用已有的会话序号索引做游标分页，不使用 OFFSET，也不受旧接口 500 条上限影响。私聊复用 Pi 当前分支，先选择页面再解析该页附件；这减少 HTTP、附件解析与浏览器负担，但不改变 Pi 本身加载会话文件的机制或模型上下文长度。

专项验证：`test/history-pagination.test.ts`、`test/history-pagination.browser.mjs`。浏览器测试覆盖 320/390/1440px、图片请求数量、滚动锚点、160 条窗口、搜索定位、会话切换时的过期搜索响应，以及空历史刷新。
流式顺序专项：`test/streaming-order.test.ts`、`test/streaming-order.browser.mjs`，覆盖时间戳偏差、连续消息、后续排队消息、刷新/快照/分页、生成完成及普通/私密会话；逐次检查完成阶段的 DOM 渲染，包括延迟旧响应、提前入库、读取时序不一致及重连快照。
