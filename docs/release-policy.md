# GitHub Release 发布规则

适用仓库：`Tylogi/YourChar`。

**状态：已采用，仓库所有者于 2026-10-29 确认。** 后续发布统一使用本模板和附件规则。
每次先准备完整正文与附件清单供审核，获得该次内容的确认后再发布或修改 GitHub Release。
模板本身无需重复确认；采用模板不构成对其他版本或历史 Release 的批量修改授权。

## 公开说明模板

以 [TEMPLATE.md](releases/TEMPLATE.md) 为唯一的正文模板，按固定顺序填写：

1. **标题与版本状态**：标题为 `YourChar <tag>`；明确稳定版或预览版。
2. **本次更新**：通常选 3–6 项用户可感知的变化，说明使用效果。
3. **下载与安装**：列出本次实际提供的平台、架构、最低系统要求、直接下载链接及
   真实的签名／公证状态；提供简短安装步骤和校验文件链接。
4. **升级与注意事项**：说明退出、备份、替换安装、数据迁移和影响使用的已知限制。
   没有特殊迁移时不添加空洞的迁移说明；不要为了缩短正文省略真实风险。
5. **English summary**：用 2–4 句概括主要变化、支持平台及关键安装或升级限制。
6. **源码链接**：只列一次构建对应的 commit 短链接。

中文是主说明语言，英文摘要不重复整篇内容。不另加长篇“构建验证”或“公证记录”章节。
签名、公证及校验结论应有实际验证记录支撑；未执行、跳过和未覆盖的检查不写成通过。
最低支持系统与实际测试过的系统不能混为一谈。

正文不粘贴完整哈希、公证提交 UUID、精确执行时间、测试逐项明细、上传重试过程，
也不另行摘录签名者姓名、Team ID、账号或本机信息。通用安装／数据目录可以出现在
必要的操作说明中，例如 `~/Library/Application Support/YourChar`；操作机器上的实际
用户名、绝对工作路径及网络配置不应公开。安装包内正常携带的公开签名证书不属于
应删除的构建记录。

## 附件清单

仅上传本次实际发布的平台产物，版本和文件名保持一致：

| 平台 | 默认公开附件 | 用途 |
| --- | --- | --- |
| macOS Apple Silicon | `YourChar-<version>-macos-arm64.dmg` | 首选安装方式 |
| macOS Apple Silicon | `YourChar-<version>-macos-arm64.zip` | 同一应用的备用格式 |
| Windows x64 | `YourChar-Setup-<version>-windows-x64.exe` | Windows 安装器 |
| 所有已发布平台 | `SHA256SUMS.txt` | 本次公开安装包的 SHA-256，整个 Release 共用一份 |

macOS 单平台默认 3 个附件，Windows 单平台默认 2 个附件；同时发布两平台时合并
安装包清单并共用校验文件。其他平台或额外产物必须在当次审核清单中明确列出并确认，
不因为构建目录中出现了文件就上传。GitHub 自动生成的源码归档不计入手动附件清单。
预览版保持现有带平台的 tag 习惯，附件版本取应用实际版本，完整 tag 则用于下载 URL。

`SHA256SUMS.txt` 只列本次公开安装包的最终文件名与哈希；在签名、公证及凭证附加完成后
重新计算。DMG 和 ZIP 必须包含同一版本、同一源码构建的应用。平台本次未更新时，
可以链接到旧版，但不把旧安装包复制到新 Release 中冒充本次产物。

以下文件留在已被 Git 忽略的 `release/<tag-or-build>/` 目录，不作为公开附件：

- `verification-*.json`、公证回执、原始公证日志及提交编号记录；
- 测试报告、截图、调试输出、构建与上传日志；
- `state.json`、`publication.json`、上传清单、临时脚本及重试记录。

私钥、密码、Token、凭据文件、真实用户数据及备份不得进入源码或发布包。
如确实需要额外公开诊断材料，先生成脱敏后的独立文件并列入审核清单。

## 发布前确认

1. 在本地准备最终标题、tag、源码 commit、稳定／预览状态、完整正文，以及带文件名、
   大小和 SHA-256 的精确附件清单。完成构建、签名、公证、必要测试及隐私检查。
2. 给仓库所有者展示正文预览和附件清单。如果是更新已有 Release，明确哪些说明会
   替换、哪些附件会新增或移除；不能把批准模板理解为批准删除历史附件。
3. 收到对这份具体内容的明确确认后再发布。若当次任务已确认相同内容，直接执行，
   不重复询问；若版本、安装包、附件范围或正文有实质变化，再确认变更部分。
4. 按确认的明确路径列表上传，禁止 `release/*` 或整目录上传。发布后核对公开说明、
   附件清单、下载链接和文件哈希，并保留本地核对记录。

根目录 [AGENTS.md](../AGENTS.md) 引用本规则，作为后续发布任务的入口。
每次发布以该次最终内容的授权为准，不重复请求采用已经确认的模板。
